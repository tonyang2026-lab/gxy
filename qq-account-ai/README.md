# 独角兽：普通 QQ 账号 + Ollama

独立项目，不使用官方机器人AppID/AppSecret。非官方账号自动化可能导致账号受限；使用专用测试号，仅在获得同意的群启用，保护登录凭证。程序不会自动加好友、入群或批准邀请。

## Windows 操作

1. 安装 Node.js 24，保持已有 Ollama 服务运行（127.0.0.1:11434），已下载 qwen2.5:3b。
2. 从 NapCatQQ 官方项目 https://github.com/NapNeko/NapCatQQ 获取 Windows 安装方式，按该项目当前文档安装并用专用QQ号登录。不要把登录二维码、密码和令牌发给别人。NapCat的具体安装界面随版本变化，以官方项目为准。
3. 在 NapCat 管理界面网络配置中新增 **WebSocket 服务端（正向）**，监听地址设置 **127.0.0.1**，端口 **3001**。启用消息事件上报，将消息格式设为 **Array/数组**，配置至少16字符的随机Token，保存启用。不要选择反向WebSocket客户端，不向公网开放管理端和消息端口。
4. 双击根目录 `启动QQ账号AI.bat`，首次会生成 `.env` 并打开记事本。填写 ONEBOT_TOKEN（和NapCat相同）、ALLOWED_USERS（允许的好友QQ号码）、ALLOWED_GROUPS（允许的QQ群号），多个号码用英文逗号分隔。保存、关闭后再次双击启动。
5. 看到“QQ账号接口已连接”及模型就绪，先用允许列表中的好友发“你好”，再到允许群里@这个QQ号或发送“独角兽你好”。这是普通账号，不会显示官方机器人标识。

配置示例（替换为自己的号码和随机令牌）：

```dotenv
ONEBOT_WS_URL=ws://127.0.0.1:3001
ONEBOT_TOKEN=替换为至少16字符的随机令牌
ALLOWED_USERS=123456789
ALLOWED_GROUPS=987654321
GROUP_AUTO_REPLY=true
OLLAMA_BASE_URL=http://127.0.0.1:11434
OLLAMA_MODEL=qwen2.5:3b
```

空允许列表不回复任何人；明确希望对所有好友或所有已加入群生效时，对应列表可填 `*`，不建议首次测试使用。机器人只处理纯文本片段，忽略图片、语音与文件；无视觉、联网、电脑操作能力。不会读取旧聊天记录。私聊直接回复；群聊@或叫名字触发，其余消息经过保守规则及本地模型判断，自动参与有60秒冷却。上下文按群/私聊及用户隔离，只保留内存中的近期对话，重启清空。不保存群聊天正文。

运行时保持 NapCat、Ollama和本程序都在运行。按Ctrl+C退出。连接断开自动退避重连；发送失败或状态未知不自动重发，避免重复发言。最多5条排队，每用户5秒间隔。模型请求最长等待120秒，旧消息跳过。

## 验证与限制

运行 `npm test` 验证本地消息路由、允许列表、重复过滤及事件格式。开发环境没有登录真实QQ账号，因此没有验证真实NapCat端到端接入；不要将接口连通视为发送已成功。如果接口连接成功但收不到消息，检查事件上报、Array格式、允许列表及账号登录状态；如果模型错误，先在命令行 `ollama run qwen2.5:3b` 测试。

## 内置工具箱

发送“独角兽帮助”查看。群里每条命令都需在前面加“独角兽”或@AI账号（@后空格再输入命令）；私聊无需前缀。仍需在允许列表内。普通文本命令由程序执行，不依赖模型，原有5秒频率限制仍适用。

| 功能 | 命令示例 |
| --- | --- |
| 井字棋（人机） | 独角兽井字棋 → 独角兽落子 5 → 独角兽棋盘 |
| 猜数字 | 独角兽猜数字 → 独角兽猜 50 |
| 结束游戏 | 独角兽结束游戏 |
| 随机骰子 | 独角兽掷骰子 3 |
| 抛硬币 | 独角兽抛硬币 |
| 选项抽签 | 独角兽抽签 火锅\|烧烤\|面条 |
| 个人待办 | 独角兽添加待办 写周报 → 独角兽待办 |
| 完成或删除 | 独角兽完成待办 1 / 独角兽删除待办 1 |

井字棋人先手❌、AI后手⭕，支持合法落子验证与胜负/平局判断，使用本地Minimax算法，不是模型模拟走棋。猜数字为1～100，10次机会。棋盘、数字题和待办按会话与发言人隔离，最多500个会话；会话24小时未使用或程序重启即清空。待办最多30项，属于个人清单，不是共享群清单，勿作为重要任务唯一记录。抽签/骰子使用系统随机源，不涉及金钱下注。

更新时关闭旧AI窗口，解压新版，将旧qq-account-ai/.env复制到新版同名文件夹，再启动新版根目录的启动QQ账号AI.bat。不要同时运行两份，否则可能重复回复。NapCat及Ollama可继续运行。当前仍无中国象棋、联网搜索、图片识别或定时推送。

## AI 新闻查询和每小时推送

新增命令“独角兽AI新闻”（私聊可省略名字）。读取 TechCrunch AI RSS 和 The Verge AI Atom 的真实公开条目，不依赖模型记忆，不需要新闻API密钥。显示来源、北京时间、原始标题和原文链接；当前不自动翻译或核验新闻观点。只取近48小时已发布条目，最多5条，缓存5分钟。每小时检查属于定时更新，不保证秒级实时或覆盖所有AI新闻。

在本机 `.env` 追加下面配置可每小时向明确指定群推送（该群需已加入并允许发送消息）：

```dotenv
NEWS_ENABLED=true
NEWS_GROUPS=416180904
```

同时确认该群已包含在 ALLOWED_GROUPS 中。多个推送群用英文逗号分隔，NEWS_GROUPS不接受星号。首次检查在启动一小时后，之后约每小时检查一次（存在最多一分钟调度偏差）；没有新条目则不发送，离线不发送，电脑关机或程序关闭时不会运行。手动查询可立即验证新闻源连接。要停止定时推送，改 NEWS_ENABLED=false 并重启。

已提交推送的链接哈希保存在 `qq-account-ai/data/news.json`，重启后继续去重，不保存新闻正文。请更新时一并复制旧data文件夹以保留去重。首次启动可发送近48小时最多5条，后续每轮最多5条未推送新闻；网络失败不会编造新闻，控制台提示失败。为避免重复消息，发送前登记链接，发送失败或结果未知不自动重发，因此可能漏掉本轮新闻，可用手动查询补看。部分来源失败时使用成功来源；新闻站点不可达时需先解决本机网络访问。

开发云环境访问这两个源均被网络网关拒绝（403），因此未验证真实源在线抓取；已用RSS/Atom样例验证解析、日期过滤、部分失败、缓存、持久去重、推送时序和允许列表。真实QQ推送需要用户本机测试，测试期间没有向任何QQ发送消息。
